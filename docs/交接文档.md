## 1. 项目概述

**EchoCare** 是一个情感陪伴机器人项目，基于开源硬件与小智 AI 固件二次开发。

| 项目 | 内容 |
|------|------|
| 硬件原型 | Moji 2.0（ESP32-C5），来源 https://oshwhub.com/movecall/moji2 |
| 固件 | 小智 AI 固件 xiaozhi-esp32 v2.2.3（ESP-IDF v5.5.5） |
| 网页前端 | personality-site/（智能体/语音/人格管理控制台） |
| 当前阶段 | 面包板手搓验证版（ESP32-S3 N16R8）已跑通核心链路 |

### 两条硬件路线

1. **Moji 2.0（原板）**：ESP32-C5 芯片，圆形外壳小机器人
2. **面包板版（当前在做）**：ESP32-S3 N16R8 开发板 + 杜邦线搭建，零焊接


**网络代理问题**（容易踩坑）：
- 代理软件（Clash Verge）监听端口是 **7897**（不是默认 7890）
- 如果 push 报 `via 127.0.0.1`，执行：

```powershell
git config --global http.proxy http://127.0.0.1:7897
git config --global https.proxy http://127.0.0.1:7897
git push
```

- 如果报直连超时（无 `via` 字样），则清除代理直连：

```powershell
git config --global --unset http.proxy
git config --global --unset https.proxy
git push
```

### 已设置的环境变量（解决中文路径编码）

```powershell
setx PYTHONUTF8 1
setx PYTHONIOENCODING utf-8
```

### 标准编译烧录流程

在「ESP-IDF 5.5 CMD」窗口执行（**务必英文路径**）：

```powershell
cd /d C:\Users\phorh\Desktop\echocare\xiaozhi-esp32-main
idf.py set-target esp32s3     # 首次切换芯片目标时执行
idf.py menuconfig             # 选板卡 + 屏幕型号
idf.py build                  # 编译
idf.py -p COM3 flash          # 烧录（COM3 是板子串口）
idf.py -p COM3 monitor        # 查看串口日志
```

串口日志监视器快捷键：退出 `Ctrl+]`，帮助 `Ctrl+T` 后 `Ctrl+H`。

## 6. 硬件接线（面包板版，ESP32-S3）

### 引脚对照总表

| 模块 | 引脚名 | ESP32 引脚 |
|------|--------|-----------|
| 麦克风 INMP441 | WS | GPIO 4 |
| 麦克风 INMP441 | SCK | GPIO 5 |
| 麦克风 INMP441 | SD | GPIO 6 |
| 喇叭功放 MAX98357 | DOUT | GPIO 7 |
| 喇叭功放 MAX98357 | BCLK | GPIO 15 |
| 喇叭功放 MAX98357 | LRCK | GPIO 16 |
| 屏幕 OLED | SDA | GPIO 8（**已改**） |
| 屏幕 OLED | SCL | GPIO 9（**已改**） |
| 屏幕 OLED | VCC | 3V3 |
| 屏幕 OLED | GND | GND |
| BOOT 按键 | — | GPIO 0 |
| 触摸传感器 TTP223 | SIG | GPIO 47 |
| 音量+ 按键 | — | GPIO 40 |
| 音量- 按键 | — | GPIO 39 |
| 板载 LED | — | GPIO 48 |
| 台灯控制（MCP） | — | GPIO 18 |

### 电源桥接（面包板必需）

- ESP32 `3V3` → 面包板红排
- ESP32 `GND` → 面包板蓝排

> 没有这两根桥接线，面包板供电轨是悬空的，所有模块都"没电"。
